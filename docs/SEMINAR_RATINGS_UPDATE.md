# Оценки участников и редактор семинаров

## Применение в Supabase

На базе, где уже выполнено предыдущее обновление семинаров (`aquageo-3`), откройте SQL Editor и выполните **целиком** файл `supabase/ratings_update.sql`. Затем запустите `supabase/verify_database.sql`: в первой таблице результатов должны быть только `PASS`.

Сначала примените SQL, затем публикуйте новую сборку сайта. Приложение запрашивает новые функции при загрузке семинаров, поэтому обновление базы обязательно. Изменять `.env` не требуется.

Для новой базы используйте `supabase/full_schema.sql`; для базы без предыдущего обновления — `supabase/migrate_existing_database.sql`. В них уже включены оценки, отдельно выполнять `ratings_update.sql` после них не нужно. Скрипты можно выполнять повторно: оценки, результаты тестов и сертификаты сохраняются.

Второй результат `verify_database.sql` может показывать прежние ограничения `NOT VALID`. Это отдельный список ограничений для проверки исторических данных, а не ошибки установки оценок.

## Поведение

- После ознакомления со всеми разделами участник может поставить от 1 до 5 звёзд. Если включён итоговый тест, сначала нужна успешная попытка.
- Оценка необязательна: кнопка «Позже» скрывает предложение. Она не блокирует завершение курса или выдачу сертификата.
- Один участник имеет одну оценку на семинар и может изменить её.
- На карточках, странице описания и странице регистрации показываются средняя оценка с округлением до десятых и количество оценок. Если оценок нет, отображается 5 и подпись «Пока нет оценок».
- Старое поле `courses.rating`, которое заполнял автор, не используется при отображении. Автор больше не может задавать рейтинг через сохранение семинара.
- Оценки хранятся в `course_ratings`. Чужие индивидуальные записи недоступны; публичная функция возвращает только среднее и количество. Запись возможна через `rate_course`, который проверяет завершение в базе.
- Рейтинг не изменяет сам курс и его версию, поэтому новая оценка не создаёт конфликт при одновременной работе редактора.

## Редактор

Формат выбирается из вариантов «Онлайн», «Офлайн», «Смешанный». Дата выбирается в календаре и сохраняется в прежнем формате `ДД.ММ.ГГГГ`. Старые распознаваемые даты заполняются автоматически; для нестандартной даты показано прежнее значение и предложение выбрать дату. Длительность состоит из количества и единицы; вариант «Другое» сохраняет возможность задать нестандартное расписание. Старые нестандартные значения не заменяются автоматически.

## Проверка

`npm run verify:release` проверяет lint, сканирование исходников, тесты, SQL и сборку. Тесты базы покрывают запрет преждевременной оценки, обязательный тест, приватность, запрет прямой записи, изменение одного голоса, среднее, сохранение оценок при повторной миграции и независимость сертификатов.

Локальные страницы `tests/browser/seminar-form.html` и `tests/browser/ratings.html` проверяют редактор и отправку/изменение оценки на синтетических данных. Страница оценок использует заглушки API и не обращается к удалённой базе.

Проверено 25 сентября 2026: 76 тестов, lint, сканирование, три SQL-сценария и production-сборка прошли. В браузере проверены отправка и изменение оценки, ошибка с повторной отправкой, «Позже», сохранение формата и длительности, семинар без теста и новая дата. На ширине 390 px горизонтального переполнения нет. Всплывающее окно нативного календаря не удалось проверить: при его открытии встроенный браузер завершил страницу с ошибкой; ввод и сохранение даты с клавиатуры работают. Удалённая база в ходе этой проверки не изменялась.
