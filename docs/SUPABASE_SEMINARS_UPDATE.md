# Обновление семинаров — 24 сентября 2026

Изменения в удалённый Supabase не применялись. Новый код требует обновления БД.

## Что выполнить

1. Сохраните резервную копию базы. На время обновления остановите редактирование курсов и сдачу тестов. По возможности сначала проверьте обновление на копии проекта.
2. Откройте **Supabase → SQL Editor → New query**, вставьте **целиком** файл `supabase/migrate_existing_database.sql` и нажмите **Run**. Не выполняйте отдельно исходники из `supabase/source/`: они собираются в общую транзакцию. Файл предназначен для существующей базы и сохраняет курсы, профили, попытки и сертификаты.
3. Выполните `supabase/verify_database.sql`. В первой таблице все строки должны иметь статус **PASS**, включая `seminar schema version 3`. Второй результат показывает прежние ограничения NOT VALID для отдельной проверки старых данных; это не список ошибок миграции.
4. Перезапустите backend и frontend новой версии. Обычный локальный запуск: `npm run dev`, адрес `http://localhost:5173`. Если порт занят, остановите предыдущий запущенный вами экземпляр. Сервер теперь явно сообщает о занятом порте, Vite не переключает адрес незаметно.
5. В кабинете администратора откройте семинары и укажите фактическое число академических часов. Старым курсам часы автоматически не присваиваются. Пустое поле означает, что строка с часами в новом сертификате не печатается.

Для совершенно новой пустой базы используйте `supabase/full_schema.sql` вместо миграции. Это альтернативы, выполнять оба файла не требуется. Дальнейшие проверки одинаковые.

## Что изменится в БД

- `courses.academic_hours`: число академических часов. `courses.certificate` автоматически соответствует наличию включённого итогового теста.
- `test_questions.question_type`: `single_choice`, `multiple_choice`, `true_false`, `short_answer`. Старые вопросы остаются с одним правильным ответом.
- `test_question_answers.correct_option_ids` и `accepted_answers`: ключи для новых типов вопросов. Таблица остаётся закрытой от студентов через RLS. Старое поле `correct_option_id` сохраняется.
- `certificates.academic_hours_snapshot`, `city_snapshot`, `template_version=3` для новых сертификатов. Уже выданные снимки и сохранённые PDF сохраняются.
- RPC сохранения курса, проверки ответов, завершения и выдачи сертификата получают новые правила. Внутренняя функция сохранения теста по-прежнему недоступна напрямую клиентам.
- `app_readiness()` возвращает `aquageo-3`.

Существующие семинары с включённым тестом будут обозначены как семинары с сертификатом; без включённого теста — без сертификата. Если раньше флаг сертификата был выключен при наличии теста, он включится в соответствии с новым правилом. При отключении теста его вопросы и старые попытки не удаляются. Уже выданный сертификат продолжает открываться по прежнему номеру.

## Проверка после применения

Создайте отдельный тестовый семинар. Проверьте все четыре типа вопросов, неправильную и правильную сдачу, скачивание PDF и QR. Затем создайте семинар без теста: после ознакомления со всеми разделами обучение должно завершиться без кнопки нового сертификата. Проверьте редактирование существующего курса и ранее выданный сертификат.

Правила оценки: вопрос имеет вес 1; несколько ответов засчитываются только при точном совпадении всего набора; короткий ответ сравнивается с заданными вариантами без учёта регистра и лишних пробелов, без нечёткого сравнения. Тест: 1–200 вопросов, 1–480 минут, до 10 попыток за 24 часа.

Шаблон использует имеющиеся в проекте шрифты `fonts/NotoSerif-*.ttf` и `assets/signature-kazambayeva.png`. При развёртывании backend включите эти файлы. Подпись — изображение из проекта, не ЭЦП. Организация в верхней строке берётся из `app_settings.issuer_name`; нижняя часть соответствует образцу: НИЦ «Industry 4.0», Astana IT University, И.о. директора И. М. Казамбаева; город — Астана.

В рабочем окружении `PUBLIC_APP_URL` и `CERT_BASE_URL` должны содержать действительный HTTPS-домен сайта: QR ведёт на `/verify/{номер}` этого домена. Для обычной локальной разработки используйте `http://localhost:5173`.

## Текущий локальный запуск

Для проверки использованы свободные порты: сайт `http://localhost:5175`, backend `http://127.0.0.1:4001`. Это временные переменные процесса; `.env` не менялся. `/health` отвечает 200; `/readiness` отвечает 503 до установки новой схемы. После миграции ожидается 200.

Если нужно воспроизвести этот запуск в PowerShell:

```powershell
$env:PORT='4001'
$env:DEV_PORT='5175'
$env:DEV_API_TARGET='http://127.0.0.1:4001'
$env:PUBLIC_APP_URL='http://localhost:5175'
$env:CERT_BASE_URL='http://localhost:5175'
$env:CORS_ORIGINS='http://localhost:5175'
npm run dev
```

Если уже установленная структура отличается от поддерживаемой схемы и SQL завершается ошибкой, сохраните текст ошибки и не отключайте ограничения. Общая транзакция отменит частичные изменения. Подробности переноса старых сертификатов и отката — в `MIGRATION_GUIDE.md`.
