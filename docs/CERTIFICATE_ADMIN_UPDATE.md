# Реестр сертификатов — 28 сентября 2026

## Задача

Добавить администратору просмотр всех сертификатов и отбор по курсу, поиск по ФИО/номеру/названию, ручную выдачу с проверкой прав и уникальности номера. Перенести документы из `generated-certificates` с сохранением номера, даты, ФИО и исходного PDF. Дать посетителям проверку номера без входа. Заменить регистрацию на продолжение курса для уже записанных участников. Сохранить автоматическую выдачу, старые записи и ограничения доступа.

## Использование

- **Кабинет → Все сертификаты**: поиск, фильтр по курсу, просмотр и PDF. По 25 записей на странице.
- **Управление курсами → Сертификаты курса** открывает реестр с выбранным курсом.
- **Создать сертификат**: ФИО, название курса, дата, организация, город, необязательные часы и оценка. Можно выбрать существующий курс/аккаунт или внести сведения о человеке и курсе, которых нет на сайте.
- Для старого документа укажите его прежний номер. Пустой номер получает уникальное значение автоматически. Повторная отправка той же формы не создаёт второй номер.
- Сохранённые сведения неизменяемы. Ручная выдача не создаёт фиктивные результаты тестов или записи о прохождении разделов. Если выбран аккаунт, документ доступен в его личных сертификатах.
- Под курсами на главной и в каталоге расположена кнопка **Проверить сертификат**. Такая же ссылка есть в подвале. Страница `/check-certificate` показывает ФИО, курс, дату, часы, организацию и статус, а также ссылку на PDF.
- Карточки показывают **Продолжить курс** для записанного участника и **Открыть курс** после завершения. Прямая ссылка на регистрацию уже записанного участника перенаправляет к материалам.

## Обновление другой установки

1. Сохраните резервную копию базы.
2. На существующей базе `aquageo-3` выполните целиком `supabase/certificate_admin_update.sql` в SQL Editor.
3. Запустите `supabase/verify_database.sql`; первая таблица должна содержать только `PASS`.
4. Обновите клиент и перезапустите Express. Для локальной разработки: `npm run dev`.

Новые установки и полная миграция уже содержат эти изменения: `supabase/full_schema.sql`, `supabase/migrate_existing_database.sql`. Исходник обновления — `supabase/source/certificate_admin.sql`; сборка — `npm run sql:build`.

## Импорт PDF

Папка `generated-certificates/` и архив `generated-certificates.zip` исключены из Git. Перед импортом разместите локальные PDF, CSV и файл метаданных в этой папке; свежий клон репозитория их не содержит. Автоматические тесты создают временные синтетические сертификаты и не требуют этих документов.

`generated-certificates/certificate_metadata.json` содержит общее название курса, организацию и город, сверенные со всеми 39 PDF. CSV без заголовка содержит девять столбцов: номер, фамилия, имя, полное ФИО, часы, дата, имя файла, исходная ссылка, SHA-256.

```sh
node scripts/import-generated-certificates.mjs
node scripts/import-generated-certificates.mjs --apply
```

Первая команда проверяет файлы и выводит план. Вторая записывает каждый сертификат и исходный PDF одной транзакцией. Повторный запуск принимает только совпадающие данные и PDF. Конфликт останавливает импорт без перезаписи; уже завершённые записи сохраняются.

Автоматическая привязка к курсу возможна только при единственном точном совпадении названия. Для явно выбранного курса используйте `--course-id=<UUID>`. По ФИО аккаунты автоматически не сопоставляются.

Импорт требует серверного `SUPABASE_SERVICE_ROLE_KEY`. Эта функция недоступна посетителям и авторизованным клиентам. Ручная выдача доступна только администратору: роль проверяется в Express и в PostgreSQL. Индивидуальные идентификаторы и email не входят в публичный ответ.
