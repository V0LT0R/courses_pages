# Аудит и границы безопасности

Объект аудита — исходники и SQL из courses_pages(1).zip, включая React, backend, Auth, тесты, Storage, сертификаты, env/deployment. Удалённый Supabase, реальная история данных, SMTP, инфраструктура и эксплуатационные ключи не проверялись. Это аудит с исправлениями и автоматическими тестами, не независимая сертификация безопасности.

| Найденное | Изменение / результат |
|---|---|
| Два backend/Auth-контура и две базы для обучения/сертификатов | Supabase — единый источник; локальный JWT/login/seminars API удалён из runtime |
| TOCTOU между удалённой eligibility-проверкой и локальной INSERT | issue_certificate проверяет состояние и создаёт snapshot внутри одной БД-транзакции |
| Certificate JSON открывал external_user_id внутри signed_json | Публичный whitelist; исходное legacy JSON хранится приватно |
| Повторная выдача зависела от повторной проверки актуального профиля/курса | Сначала существующая immutable запись; уникальность user/course |
| expected_updated_at можно было не передать | Обязательный concurrency token на обновление, FOR UPDATE и версия/история курса |
| Удаление раздела каскадно удаляло отметки | Запрет удаления раздела с прогрессом, rollback всей редакции |
| NULL роль могла пройти проверку NOT IN | Явное coalesce и запрет отсутствующей роли |
| Время сдачи фиксировалось до ожидания блокировки | clock_timestamp после FOR UPDATE, deadline проверяется в БД |
| Вопросы/варианты/score могли зависеть от слабой старой схемы | Матрица RLS, запрет прямой записи, проверка question/test/version/option, duplicate rejection; composite FK |
| Предыдущие дополнительные grants/policies могли сохраняться | Пересоздание политик прикладных таблиц и отзыв старых table/column write grants |
| Правильные ответы | Отдельная таблица, доступ только управляющему курсом; student SELECT возвращает пустой набор |
| Проверка сигнатур загрузки выполнялась в браузере | Серверная проверка байтов, Auth+role, UUID-путь, size/concurrency limits, запрет прямых Storage writes |
| Общий кеш разделов переживал смену пользователя | Ключ с user ID, очистка на auth-событиях, защита устаревших загрузок |
| Публичный certificate URL зависел от env/host/fallback | Один проверенный origin, production HTTPS, отсутствие доверия Host/forwarded-host |
| PDF зависел от системных шрифтов, длинные строки перекрывались | Встроенный лицензированный шрифт, ограниченные блоки текста, стабильные даты/байты |
| Неограниченная одновременная генерация PDF | Четыре обработки на процесс, объединение запросов по номеру, DB PDF cache |
| Излишние запросы за signed URLs / большой главный bundle | Пакетный Storage API, lazy pages, пагинация каталога |
| Ошибки RPC показывали SQL Editor/schema cache посетителю | Общий перевод ошибок и generic backend ошибки, request ID |
| Исходный lockfile ссылался на внутренний registry | Публичные registry.npmjs.org resolved URL, проверка npm ci |
| В исходном ZIP были `.env` и `.git` | Они исключены из итогового архива; значения не публиковались |

## Существовавшие хорошие решения

В исходнике уже были UNIQUE для enrollment/progress, частичный индекс активной попытки, RLS по ролям, разделённая таблица ответов, server-side scoring, CORS и rate limiter. Они сохранены и усилены. Наличие защиты проверяется поведением SQL/API, а не утверждением, что всё было написано заново.

## Дополнительные области проверки

SQL выполняется через фиксированные RPC и параметризованные запросы импортёра; пользовательский ввод не конкатенируется в SQL. HTML сертификата экранируется; React не использует dangerouslySetInnerHTML, учебный текст выводится как текст. URL материалов ограничены HTTP(S); backend не делает fetch произвольных URL. Файлы не распаковываются и не исполняются; их имя генерируется UUID. Bearer JWT проходит getUser; подписыванием/проверкой Supabase-токенов не занимается самописный JWT-код. Cookie-auth не используется, поэтому браузер не отправляет credential автоматически в cross-site mutation; CORS дополняет, но не заменяет проверку токена.

Course catalog публичный по текущему продукту. ФИО/семинар/дата/оценка сертификата доступны обладателю уникального URL; email и internal user UUID не выдаются. У старых сертификатов энтропия номера определяется предыдущим выпуском и не может быть увеличена без изменения URL. Выданный QR/URL предполагает возможность добровольно делиться сертификатом.

Администратор/создатель курса может менять программу и знает правильные ответы своего теста. Snapshot ФИО доверяет profiles, но profile name сам вводит пользователь. Не реализованы верификация личности и защита от подсказок другим человеком. Успешные исторические результаты остаются действительными при новой версии теста; полный сменённый учебный план следует оформить новым курсом.

## Что обязательно проверить в вашей инфраструктуре

- Реальные RLS/ACL неизвестных таблиц/RPC, действующие Edge Functions, Auth CAPTCHA/rate limits, SMTP, redirect allowlist и email confirmation.
- Старые сертификаты: сопоставление и импорт, конфликты/подозрительные результаты, существующие внешние потребители signed JSON.
- HTTPS/reverse proxy/CSP, доступ к origin, мониторинг и нагрузка. Лимиты в памяти не распределённые; защита Supabase требует отдельной настройки.
- Signed URL действует до часа, в том числе после выхода пользователя; это bearer-ссылка. Сигнатура файла не доказывает отсутствие вредоносного PDF — при недоверенных авторах нужен антивирус/карантин.
- Вкладки одновременно используют серверную попытку, но несданные выбранные ответы находятся в памяти вкладки: после перезагрузки их надо выбрать заново, дедлайн не сбрасывается. Автосохранения черновика ответов нет.
- Кеш PDF фиксируется при первом скачивании. Смена домена после первого PDF требует сохранения старого домена/редиректа; скачанный документ нельзя переписать. Отзыв проверяется онлайн, ранее сохранённый PDF остаётся прежним.
- Страницы анкеты и аналитики используют публичные Google Forms/Sheets. Опубликованный CSV доступен независимо от RLS приложения; не публикуйте там персональные поля. Google Forms no-cors response не подтверждает принятие ответа; интерфейс больше не обещает гарантированный успех.

В исходном `.env` были DATABASE_URL, JWT_SECRET и Ed25519 private key. Если исходный ZIP или история Git передавались посторонним, смените соответствующие секреты; удаление их из нового архива не отменяет прежнего раскрытия. Перед production используйте отдельный серверный Supabase ключ и не публикуйте историю старого репозитория без проверки.

Источники решений: [Supabase RPC security](https://supabase.com/docs/guides/database/functions), [Supabase private buckets](https://supabase.com/docs/guides/storage/buckets/fundamentals), [PostgreSQL locking](https://www.postgresql.org/docs/current/explicit-locking.html). Тесты не доказывают отсутствие всех уязвимостей; фактическое выполнение отражено в VALIDATION_REPORT.md.
