# Архитектура версии 2

React/Vite + Supabase Auth/REST/Storage + Express. Вся новая информация об обучении и сертификатах находится в одном Supabase PostgreSQL. Дополнительная DATABASE_URL для работы сайта не нужна. Дизайн и существующие маршруты сохранены; добавлены восстановление пароля, страница списка сертификатов и пагинация каталога.

| Операция | Авторитетный уровень | Гарантия |
|---|---|---|
| Вход/refresh/logout | Supabase Auth | Проверка JWT на сервере через getUser; роль из profiles |
| Запись | enroll_in_course | UNIQUE(user_id, course_id), INSERT ON CONFLICT |
| Прогресс | mark_section_completed | UNIQUE(user_id, section_id), серверное время |
| Начало теста | start_course_test | Блокировка курса, advisory lock пользователя/курса, partial UNIQUE active attempt |
| Сдача | submit_course_test | FOR UPDATE попытки; clock_timestamp после получения блокировки; подсчёт только в БД |
| Редактирование | save_course_with_content | Одна транзакция; обязательный expected_updated_at; course_revisions |
| Сертификат | issue_certificate | Проверка обучения + снимок + завершение enrollment в одной транзакции |
| PDF | Express + certificate_pdfs | Встроенный шрифт, детерминированное формирование, сохранение первой версии файла |
| Публичная проверка | Express + whitelist | Высокоэнтропийный номер, без email, user_id, внутренних UUID или исходного signed_json |
| Загрузка | Express + private Storage | Проверка Auth/роли, лимит, сигнатура, UUID-имя; прямые browser upload запрещены |

Порядок блокировок: курс → advisory lock пользователя/курса → попытка/профиль. Редактирование получает эксклюзивную блокировку курса; выдача и старт теста — совместную. Транзакции выполняются в READ COMMITTED; UNIQUE остаётся защитой целостности независимо от прикладных проверок. Коллизия hashtext может лишь временно сериализовать независимые запросы, а не смешать их данные.

Курс имеет revision; при изменении сохраняется предыдущий снимок курса/разделов/блоков. Вопросы теста версионируются и не удаляются. Старые попытки оцениваются по своей версии и снимку проходного балла/времени. Прогресс означает факт ознакомления, не доказательство чтения или усвоения. Изменение текста раздела не обнуляет предыдущую отметку. Нельзя удалить раздел, для которого уже существует прогресс; для принципиально новой программы создавайте новый курс. Уже полученный успешный результат любой сохранённой версии остаётся действительным; новый сертификат требует ознакомления со всеми текущими разделами. Это сознательная политика совместимости.

Сертификат единственный на пользователя/курс, даже после отзыва; повторная выдача возвращает ту же запись со статусом revoked. ФИО является снимком профиля, заполненного пользователем: система не подтверждает личность по документам. Преподаватель с доступом к своему тесту знает ответы — это предусмотренная роль.

Первый запрос PDF сохраняет байты, SHA-256 и verification_url. Последующие загрузки возвращают тот же файл даже после обновления шаблона. SHA-256 является проверкой целостности сохранённого файла, не электронной подписью. Юридически значимая подпись не заявляется. Источником статуса отзыва служит онлайн-проверка; ранее скачанные PDF не изменяются.

Legacy: старый Express использовал local_certificate_records в другой БД. Скрипт импорта сохраняет все старые записи в закрытой legacy_certificates и переносит первую запись группы в certificates. Старые номера продолжают работать. Несопоставленные записи и повторный импорт описаны в MIGRATION_GUIDE. Оригинальное private signed_json не публикуется; маршрут /json теперь отдаёт безопасные поля и статус, поэтому внешние потребители старого формата должны быть обновлены.

Границы: Node не выполняет произвольный SQL и не скачивает URL из пользовательских данных; SSRF-пути в новой генерации PDF нет. RLS не ограничивает владельца БД и service_role: ключ сервиса остаётся серверным секретом. Существующие Google Forms/Sheets используются страницами анкеты/аналитики независимо от курса; их доступность и приватность требуют отдельной настройки владельцем.
